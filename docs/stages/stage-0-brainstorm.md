## 1. Уточняющие вопросы — ответы

### 1.1 Аудитория и масштаб

1. **Личный pet**, с опцией коммерции позже; стек выбран осознанно (не «учёба с нуля»).
2. **Мультиюзер сразу** (базовый): свои топики + просмотр чужих.
3. Синхронизация через **аккаунт**.
4. **Free**.

### 1.2 Ранжирование

5. MVP: **drag-and-drop**.
6. Порядок **строгий** (1…N), без ничьих.
7. Есть **inbox / «на будущее»** отдельно от ранжированных.
8. Новый элемент → **inbox**, ранжирование отдельно.

### 1.3 Категории и сущности

9. **Пресеты + произвольные** категории/топики.
10. Поля: **название, обложка, дата добавления** (система). Дата потребления — later (`ideas`). Статуса нет: только оценённые / ещё не оценённые.
11. Без подкатегорий.

### 1.4 Импорт и медиа

12. Импорт внешних сервисов — **нет**.
13. Обложки — **upload пользователем**.
14. Визуал **свой**, современный (не клон Letterboxd).

### 1.5 Социальность

15. Публичные ссылки — **да**.
16. Ссылка на **конкретный топик**.
17. Лайки / follow / комменты — **не решено** → выносим из MVP.

### 1.6 Платформа

18. Web + **PWA**; натив — позже, способ TBD.
19. Offline — **не обязателен**.
20. Backend: **отдельный repo, Nest.js**. _(Пересмотрено 05.10.2026: моно-репо, Nest — отдельный деплоимый контур; см. `../process/decisions.md`, «Этап 3 — стек».)_
21. UI: **только русский**.

### 1.7 Ценность

22. Удобство ведения рейтинга + **шаринг друзьям**.
23. Старт: фильмы, сериалы, книги, игры.
24. Критерий успеха MVP пока слабый («открывается в браузере») — зафиксировать на Этапе 1.

### Пояснение риска 10 (конфликты) — простыми словами

**Сценарий:** топик открыт на телефоне и в браузере. На телефоне поставили фильм на 3-е место и сохранили. В браузере всё ещё старый список; там перетащили другой фильм и нажали сохранить — без защиты **перезапишется** порядок с телефона.

**Что хотим продуктово:** если данные на сервере уже новее, чем те, с которых пользователь редактировал — не делать тихий overwrite. Показать что-то вроде «список обновился» → перезагрузить актуальный порядок → править снова.

**Чего не делаем в MVP:** сложный merge двух порядков вручную (как в git). Техника (версии, ETag и т.п.) — на тех-этапе.

_Отложено в реализации 05.10.2026: UX «список обновился» и проверка версии в первый slice не берём (до этого возможен тихий overwrite); см. `../process/decisions.md`, `../backlog/ideas.md`._

## 3. MVP vs v2 vs nice-to-have (MoSCoW)

### Must (MVP)

- Регистрация / логин (email+password достаточно; OAuth — позже)
- Профиль: **ник** + список **public**-топиков
- Создание топика: подсказки к названию (не пресет-сущность); категории — later (`ideas` при желании)
- Элементы: название, обложка (upload), **дата добавления** (система); дата потребления — later (`ideas`)
- Два состояния элемента: **ещё не оценён** (inbox) и **оценён** (в строгом рейтинге)
- Перенос inbox → ranked (с выбором позиции или «в конец» + DnD)
- DnD переупорядочивание ranked (desktop + приемлемый touch)
- Альтернатива DnD: переместить на позицию N / ↑↓ (для a11y и мобилки) _(отложено в реализации 05.10.2026, см. `../process/decisions.md`)_
- Приватность топика: private / unlisted / public; **дефолт unlisted**
- Публичная страница топика по ссылке (в т.ч. unlisted)
- Просмотр public-топиков другого пользователя (простая страница профиля)
- **Подписка на пользователя** + **лента друзей** (public-топики тех, на кого подписан)
- Лендинг
- Адаптив; PWA как продуктовое «можно поставить на домашний экран» (без обязательного offline)
- UI на русском
- _(Архитектура репо/Nest/деплой — вне этого списка, отдельный тех-этап)_

### Should (сразу после MVP / v1.1)

- Виртуализация длинных списков
- Поиск по элементам внутри топика
- OG-превью для шаринг-ссылок
- Ресайз/оптимизация обложек
- Базовая модерация/репорты публичного контента
- Подтверждение email / сброс пароля (если не было в MVP)

### Could (v2)

- «Вставить между A и B»
- Попарные сравнения / Elo для помощи в ранжировании больших списков
- Ничьи / tier-группы
- Подкатегории или несколько рейтингов в одной теме
- Лайки, комментарии, богатый activity-stream (каждый DnD в ленту)
- Импорт CSV / Letterboxd / Kinopoisk и т.д.
- i18n (EN)
- Кастомные поля по типу пресета
- Коллаборативные топики (несколько редакторов)
- Онбординг / guided empty state (см. [`../backlog/ideas.md`](../backlog/ideas.md))
- **Теги** у элементов (в т.ч. прохожу / прошёл / забросил) — см. [`../backlog/ideas.md`](../backlog/ideas.md)
- Отдельное поле «статус» — не планируем, пока закрываем тегами

### Won’t (сейчас)

- Нативные iOS/Android store-приложения
- Полноценный offline-first / CRDT
- Монетизация, подписки, реклама
- Парсинг чужих API за метаданными/постерами
- Сложный discovery («как TikTok для рейтингов»)

```text
MoSCoW (сводка)

MUST     Auth, лендинг, топики, элементы (без статуса), inbox/ranked, DnD+позиция, privacy (default unlisted), share, профиль, follow+лента public-топиков, PWA-shell, RU
SHOULD   Виртуализация, поиск, OG, оптимизация картинок, репорты
COULD    Smart-rank UX, теги, лайки/комменты, импорт, i18n, коллаборация, онбординг
WON'T    Native stores, offline-first, money, внешние метаданные API, статус как отдельное поле (пока)
```

## 4. Конкурентный анализ

| Продукт        | Что хорошо                                                                  | Что слабо / не наше                                                  | Чем отличаемся                                                                           |
| -------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **Letterboxd** | Сильный соцграф, дневник просмотров, визуал постеров, привычка «логировать» | Оценка ★ + лайки, не **полный личный порядок**; только фильмы        | Мы — **универсальные топики** + акцент на **ранге**, не на звёздах; свой визуальный язык |
| **Goodreads**  | Огромный каталог книг, прогресс чтения                                      | Устаревший UX, ★-оценки, мало «мой строгий топ»                      | Узкий фокус на **личном порядке** + шаринг топа, без каталога-гиганта                    |
| **Backloggd**  | Игры, статусы, соц. активность                                              | Снова скоринг/статусы важнее строгого ранга всей библиотеки          | Inbox → ranked + DnD как первичный UX                                                    |
| **Serializd**  | Сериалы, сезонность, трекинг                                                | Ниша сериалов; рейтинг не = полный порядок                           | Пресеты включают сериалы, но модель общая для любых сущностей                            |
| **TierMaker**  | Понятный tier-list, вирусный шаринг картинки                                | Тиры (S/A/B), не полный порядок; мало «ведения» коллекции во времени | Мы — **живой** список с inbox и аккаунтом, не разовый коллаж                             |
| **Ranker**     | Попарные голосования, UGC-рейтинги                                          | Часто «интернет голосует», не личный канон; шумный контент           | Личный канон пользователя + опциональный паблик                                          |
| **Beli**       | Мобильный UX «рейтинг мест», социальность                                   | Ниша food/places; закрытая экосистема                                | Шире домены; web-first + PWA; pet с прозрачным стеком                                    |

### Вывод по позиционированию

- **Не** «ещё один трекер фильмов».
- **Да** «личный канон в виде упорядоченного топика + ссылка другу».
- Опасность: без отличного UX ранжирования и красивой public-страницы мы проиграем и Letterboxd (соцдоказательство), и Excel/Notion (гибкость).

**Критично:** дифференциатор должен быть виден за 30 секунд на публичной странице топика (ранг + обложки + имя автора), а не только «внутри редактора».

- Платформа: web + PWA-shell; offline не обязателен
- Backend/frontend split, Nest, хранилище обложек — обсудим отдельно

## 7. Честный продуктовый вердикт

Идея **жизнеспособна**, если не размазывать фокус:

- Сильная сторона: понятная модель **inbox → строгий ранг → share link**, универсальные топики.
- Модель элемента упрощена: без статуса, меньше путаницы с inbox.
- Рекомендация: считать MVP полезным, когда **вы сами** ведёте несколько топиков Topic и хотя бы раз отправили unlisted-ссылку — сроки не жмём.
