## 0. Стек и технологии ✅ зафиксировано (05.10.2026)

> Обсуждение в Cursor **Plan mode**. Выбран **вариант A**: Vue 3 SPA (Vite) + Nest REST + Postgres, моно-репо.

### Предпочтения владельца (приняты решением 05.10.2026)

- Frontend: **Vue 3** — принято.
- Backend: **Nest.js** — принято; остаётся отдельным деплоимым контуром (см. «Монорепо» ниже: пересмотр «отдельного repo»).
- Платформа: web + **PWA**; UI только **RU**.
- Цель pet: осознанная практика стека, не «онбординг с нуля».

### Решение

### Отклонённые варианты

- **B — Nuxt hybrid SSR + Nest:** OG и SEO сразу, но третий рантайм (Nitro/Node), пробрасывание cookie через SSR и развилка «где BFF» — ради фичи из Should (OG).
- **C — Vue SPA + BaaS (Supabase) без Nest:** быстрее до демо, но ломает предпочтение Nest, матрица видимости уходит в RLS, ранги неудобно держать вне транзакций приложения, vendor lock-in.

### Отложено / не в первом slice

Продуктовые договорённости остаются в stage-0/1; здесь — только что **не берём в реализацию сейчас** (см. также `decisions.md`, `docs/backlog/ideas.md`).

- **↑↓ / «переместить на позицию N»** как альтернатива DnD (a11y, мобильный). Возможно позже.
- **UX «Топик изменился»** и optimistic-проверка версии (`If-Match` и т.п.). Возможно позже; до этого возможен тихий overwrite порядка с двух устройств.
- **OG-превью** для `/t/:shareId`: отдельный slice после первого shippable (маршрут Nest для ботов + rewrite на edge). В stage-0 это Should; в рисках #11 записано «согласовано» — проверить формулировку при спринтах.
- **Тесты** (API и web, фреймворки, покрытие) — отдельным решением.
- **Prod-хостинг** и prod-хранилище обложек.
- **Rate-limit на auth** — не решено.
- **Способ подключения токенов в Tailwind** `@theme` (ручной файл vs генерация из `tokens.json`) — при scaffold.
