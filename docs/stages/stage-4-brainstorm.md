## YouGile и MCP

- Компания в YouGile **уже создана** владельцем.
- MCP: тот же паттерн, что на соседнем проекте — hosted endpoint, Bearer в заголовке. **Токен только локально** (`.cursor/mcp.json` или user-level config), **не коммитить**.

Пример фрагмента конфига (подставить свой ключ локально):

```json
"yougile": {
  "url": "https://yougile.com/data/ai/mcp",
  "headers": {
    "Authorization": "Bearer <YOUGILE_TOKEN>"
  }
}
```

Колонки, доски, задачи — создаём и правим **через MCP** в **новом чате** после подключения.

## Agent-workflow (черновик, детализируем в 4e)

- Колонки (зафиксированы на досках, RU): `Бэклог` → `К работе` → `В разработке` → `На проверке` → `Готово`.
- Проекты YouGile: **Frontend** (`FRO`), **Backend** (`BAC`); в каждом доска **«Задачи»**.
- **Кто двигает карточки:** реализацию берут **ИИ-агенты** (Cursor). Владелец настраивает флоу, чтобы агенты сами забирали задачи из очереди.
- Поток:
  1. Карточка создаётся в **«Бэклог»** (владелец вручную или через агента-нарезку).
  2. Доводится до контракта (AC, ссылки, out-of-scope) и переносится в **«К работе»** — это сигнал «можно брать агенту».
  3. Агент берёт карточку → **«В разработке»** (одна активная на агента/чат) → делает работу → комментарий в YouGile + запись в `task-history.md` → **«На проверке»**.
  4. Проверка: **владелец или агент-ревьюер** → **«Готово»** (или возврат в «К работе» / «В разработке» с комментарием).
- В `К работе` только карточки с AC, ссылками на `docs/` / Figma и явным out-of-scope.
- Не выходить за `tech-stack.mdc` и отложенное из stage-3 §0; commit/push — только по запросу владельца.
- Параллельные чаты: не брать одну и ту же карточку (фиксируем в rule/skill).
