## YouGile и MCP

- Компания в YouGile **уже создана** владельцем.
- MCP: тот же паттерн, что на соседнем проекте — hosted endpoint, Bearer в заголовке. **Токен только локально** (`.cursor/mcp.json` или user-level config), **не коммитить**.

Пример фрагмента конфига (подставить свой ключ локально):

```json
"yougile": {
  "url": "https://yougile.com/data/ai/mcp",
  "headers": {
    "Authorization": "Bearer <YOUGILE_TOKEN>"
  }
}
```

Колонки, доски, задачи — создаём и правим **через MCP** в **новом чате** после подключения.

## Agent-workflow (канон 4e)

Артефакты: rule `.cursor/rules/collaboration/yougile-agent-workflow.mdc`; skills `yougile-planner`, `yougile-executor`, `yougile-reviewer`; git — `git.mdc`.

### Колонки и роли

| Колонка | Кто двигает |
|---------|-------------|
| **Бэклог** | Нарезка / владелец |
| **К работе** | **Планировщик** (из Бэклога, только выполнимые по зависимостям) |
| **В разработке** | **Исполнитель** (claim только из «К работе») |
| **На проверке** | Исполнитель после сдачи + PR |
| **Готово** | **Ревьюер** после OK |

- Проекты: **Frontend** (`FRO`), **Backend** (`BAC`); доска **«Задачи»**; агенты смотрят **обе**.
- **Один чат = одна задача** (оркестратор). Команда владельца: «сделай задачу …» / «прогони пайплайн» → до Готово или стопа.
- Ревью: **subagent с пустым контекстом** (не отдельная вкладка Cursor). Handoff-пакет в комментарии YouGile.
- Возврат с Review → **«В разработке»** тому же оркестратору. Цикл Review↔Doing: **макс. 3**.

### Git

- База фич: **`develop`** (владелец создаёт вручную).
- Ветка: `feat/<ID>` от `develop` → commit/push → **PR → `develop`**.
- Коммиты по задаче: `тип(ID): краткая суть`. В описании PR: ссылка на YouGile + краткий summary.
- Ревьюер при OK: `task-history.md` → **commit** на feat → **merge** PR → **удалить** ветку → «Готово».
- В `main` агенты не пушат.

### Ревью и DoD

- Чеклист в YouGile: AC + «Как проверить» + свои кейсы; ручной прогон; стек поднимать если уже есть.
- Автотесты в репо пока **не** писать; позже — ревьюер пишет тесты (`docs/backlog/ideas.md`).
- **→ На проверке:** AC по мнению исполнителя; ветка + PR; handoff-комментарий.
- **→ Готово:** ревью OK + task-history закоммичен + PR смержен.

### Прочее

- Баги (`Errors=Bug`): тот же флоу; стикер на будущее — отдельный приоритет не фиксируем.
- `.env`: локальные дефолты из `.env.example` без спроса; прод/коммит `.env` — спросить.
- YouGile MCP: нужна открытая вкладка компании.
