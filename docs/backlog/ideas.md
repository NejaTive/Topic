## Бэклог идей

### Категории топиков
- **Статус:** нарезка YouGile ✅ / post-MVP (15.10.2026)
- **Суть:** enum категории топика + поиск в открытом API при добавлении элементов; `custom` — без автодополнения. v1: только `movies` + `custom`; провайдер фильмов — **TMDB** (выбрано 15.10.2026).
- **Карточки:** BAC-21…23, FRO-36…38 (эпик Catalog).
- **Канон:** [`../feature/catalog-enrichment.md`](../feature/catalog-enrichment.md), [`../process/decisions.md`](../process/decisions.md) (15.10.2026).
- **Было:** в MVP — только чипы-подсказки к названию на S04 (без таксономии).
- **Источник:** фидбэк по S04 Create Topic (wireframes); обсуждение enrichment 15.10.2026.

### Попарные сравнения (pairwise ranking)
- **Статус:** идея / v2+
- **Суть:** ранжировать не только DnD, а через сравнение «A vs B» — итог правит порядок в топике.
- **Зачем:** DnD плохо масштабируется на длинных списках; попарка помогает вставить новый элемент из inbox или уточнить спорные места в середине топа.
- **Черновые вопросы:** полный турнир vs выборочные сравнения; связь с Elo/скрытым score; как смешивать с ручным DnD без конфликтов.
- **Источник:** Этап 0 — Could (smart-rank UX).

### Онбординг / guided empty state
- **Статус:** идея; **не MVP**
- **Суть:** после регистрации провести через пресет → 3 элемента в inbox → первое ранжирование, чтобы не встретить пустой экран.
- **Источник:** фидбэк по риску 2.8 (empty state).

### Теги у элементов
- **Статус:** идея / после MVP
- **Суть:** свободные или полусвободные теги вместо отдельного поля «статус». Примеры: прохожу, прошёл, забросил, реворч, с друзьями.
- **Зачем:** не смешивать с placement (оценён / ещё не оценён).
- **Решение владельца:** в MVP статуса нет; теги — будущая система.
- **Источник:** фидбэк по риску 2.12 + ответы §6.

### Дата потребления у элемента (`consumedAt`)
- **Статус:** отложено / после MVP (вернуться явно)
- **Суть:** опциональное поле «когда потребил» (дата) на S06/S07; в модели — `consumedAt`.
- **Зачем:** отличать «добавил в список» (`createdAt`) от «посмотрел / прочитал / прошёл».
- **Решение владельца (04.10.2026):** убрать из hi-fi S06 и MVP-контракта; не рисовать и не закладывать в shippable slice, пока не вернёмся к этому пункту.
- **Черновые вопросы:** формат ввода (datepicker vs маска); обязательность; показ на public share / профиле.
- **Источник:** Этап 0 → затем вынесено из S06 при hi-fi.

### S08 Перенос в рейтинг (модалка)
- **Статус:** отложено / не в текущем hi-fi (04.10.2026)
- **Суть:** модалка «в конец» / «на позицию N» при переносе из inbox.
- **Решение владельца:** от S08 отказываемся на этом срезе; перенос — через S05 (DnD) и CTA «В рейтинг» с дефолтом в конец без отдельного экрана. Вернуться, когда понадобится явная позиция N / a11y без DnD.
- **Источник:** фидбэк после S07.

### S10 Публичный профиль
- **Статус:** в этапе 5 (возврат; kickoff 09.10.2026)
- **Суть:** ник + public-топики + Подписаться / Отписаться.
- **Решение владельца:** hi-fi/реализация — [`../stages/stage-5-brainstorm.md`](../stages/stage-5-brainstorm.md); модель — односторонняя подписка (follow). Ранее (04.10.2026) отложено только в срезе hi-fi этапа 2.
- **Источник:** фидбэк после отложения S13; промоут в этап 5.

### S13 Лента друзей
- **Статус:** в этапе 5 (возврат; kickoff 09.10.2026)
- **Суть:** экран ленты public-топиков людей, на которых подписан; tab «Лента» в nav.
- **Решение владельца:** hi-fi/реализация — [`../stages/stage-5-brainstorm.md`](../stages/stage-5-brainstorm.md); терминология UI — «подписка», не «друзья». Ранее (04.10.2026) отложено только в срезе hi-fi этапа 2.
- **Источник:** фидбэк после S11/S12; промоут в этап 5.

### ↑↓ / «переместить на позицию N» (альтернатива DnD, a11y)
- **Статус:** отложено после выбора стека (05.10.2026); вернуться явно
- **Суть:** кнопки ↑↓ и/или ввод позиции N как альтернатива перетаскиванию — клавиатура, screen reader, мобильный touch.
- **Решение владельца:** в первом slice только простой нативный DnD; продуктовая договорённость (stage-0 риск #9, Must) не отменена.
- **Связано:** S08 (модалка позиции) — тоже в backlog.
- **Источник:** Этап 3, выбор стека.

### Конфликт правок: «Топик изменился» + проверка версии
- **Статус:** отложено после выбора стека (05.10.2026); вернуться явно
- **Суть:** при устаревшем save не молча перезаписывать порядок; UX «топик изменился — обновить»; техника — optimistic-проверка версии (`If-Match` по `updatedAt` или отдельный `revision`) → 409.
- **Решение владельца:** в первом slice не делаем; до этого возможен тихий overwrite порядка с двух устройств.
- **Источник:** Этап 3, выбор стека (Flow E в stage-1).

### Ревьюер пишет автотесты
- **Статус:** отложено / после стабилизации agent-workflow (05.10.2026)
- **Суть:** агент-ревьюер при проверке карточки добавляет автотесты в репо (сейчас — только чеклист YouGile + ручной прогон).
- **Зачем:** снизить «зелёный на глаз» Done без регрессии.
- **Сейчас:** стратегия тестов не выбрана (stage-3); в 4e автотесты не пишем.
- **Источник:** этап 4e, обсуждение качества ревью.

### Версии в health / UI / GHCR `:X.Y.Z` (остаток B)
- **Статус:** частично снято (08.10.2026) — bump `package.json` **обязателен** перед деплоем (см. `decisions.md` / `publish-prod`).
- **Ещё отложено:** файл `VERSION`; отдавать версию в `/api/health` (и опционально в UI); теги образов GHCR `:X.Y.Z` рядом с `:sha`.
- **Зачем (отложенное):** видеть «что крутится в проде» без git; проще откат по semver-тегу образа.
- **Источник:** обсуждение версионирования перед prod-деплоем + уточнение владельца.

### S05 — accent-обводка RankedDropZone (drag-over)
- **Статус:** отложено (08.10.2026); вернуться явно
- **Суть:** зелёная обводка/ring зоны «Рейтинг» при наведении перетаскиваемого элемента (`isDragOver`).
- **Решение владельца:** визуал убрать из текущего среза; droppable + live-gap остаются.
- **Заметка при возврате:** на мобилке `ring-inset` без padding ломается (карточки перекрывают inset); предпочтительнее outer `outline`/`ring` или padding ≥ толщины ring.
- **Источник:** баг mobile layout на TopicDetailPage.

### Copy from share — already owned (флаг «уже есть»)
- **Статус:** отложено (17.10.2026); вернуться явно
- **Суть:** на share заранее знать, что элемент уже есть у текущего пользователя (дизейбл «+» / пунктов picker), а не только 409 после выбора топика.
- **Сейчас:** дедуп только в целевом топике по `meta.sourceUrl`; без `sourceUrl` — нет надёжного id.
- **При возврате:** семантика A (есть хоть в одном топике) vs B (по топикам в picker; ближе к текущему флоу); лёгкий batch при auth.
- **Источник:** обсуждение после copy-from-share; `decisions.md` 17.10.2026.

### Рекомендации (mutual recommend)
- **Статус:** нарезка YouGile / post-MVP (17.10.2026)
- **Суть:** рекомендовать свой элемент взаимным подпискам; inbox «Мои рекомендации» сверху Ленты; accept = copy в inbox своего топика (как copy-from-share). Снимок карточки; private-топик ок (шарится item, не топик).
- **Карточки:** BAC-31→28, FRO-48→46 (эпик Recommendations; порядок исполнения: Prisma → mutual → recommend → inbox → client → UI).
- **Канон:** [`../feature/recommendations.md`](../feature/recommendations.md), [`../process/decisions.md`](../process/decisions.md) (17.10.2026).
- **Источник:** обсуждение owner 17.10.2026.
